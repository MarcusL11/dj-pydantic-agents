# Version 0.1 plan

Version 0.1 has the core app, `contrib.codex`, `contrib.datastar` and `contrib.celery`. It has chat and approvals, and no tools.

The design is in the Vintage Eye repository: `docs/research/admin-ai-chat/PACKAGE.md` and `BRIEF.md`.

## Method

Each slice ends with green tests, one commit and a short report to the user.

## Decisions

1. The send, approve and stream views live in `contrib.datastar`. The core app has services only.
2. One `messages` JSON field for each conversation.
3. Fixed models with a `metadata` field. No swappable models.
4. One column on `Turn` for 7 `RunUsage` counters: `requests`, `tool_calls`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens` and `output_reasoning_tokens`. No audio counters and no `cost`.
5. A `redis` service in `compose.yml` and in CI, for the transport tests.
6. Fernet from `cryptography` for the Codex tokens. Confirm in slice 6.
7. The package uses `datastar-py` only, not `django-datastar`. `django-datastar` 0.2.0 excludes Django 6.1.
8. Primary keys are prefixed ULIDs from `python-ulid`: `cnv_`, `trn_` and `apr_`. `ids.py` has one generator for each prefix.
9. `PendingApproval.tool_call_id` is unique for each turn, not across all turns. The approve button sends `PendingApproval.id`.
10. `Conversation` has no `revision` field. The row lock and the active-turn constraint make the turns run one at a time.
11. `Turn.prompt` keeps the user message. Nothing clears it. A failed turn clears `Conversation.pending_approvals` and keeps `messages`.
12. The repositories return their own DTOs from `dtos/`, and raise the errors in `errors.py`.

## Facts from the research

The reports are in `.pi/research/v0.1/`.

- A turn calls `run_sync(message_history=..., deferred_tool_results=..., event_stream_handler=...)`.
- Do not pass `conversation=`. With it, the default `request_limit` of 50 counts the requests of the whole conversation. The package keeps the conversation total in its own columns.
- The event handler must be `async`. The first text piece is in `PartStartEvent`. The next pieces are in `PartDeltaEvent`.
- An approval resume does not trigger the Codex "suspended run" error. That error needs OpenAI background mode. Keep background mode off.
- `OpenAICodexOAuthFlow.exchange_code()` does not check `state`. The login service must check it.
- The refresh lock of the Codex provider works in one process only. Slice 6 needs a lock across processes.
- A new prompt fails when the history ends with a tool call that has no result. This happens after a failed resume. `pydantic_ai.messages.repair_messages()` closes the open calls. In 2b, the kit runner must call it before a new prompt.
- `DeferredToolRequests.build_results()` raises `ValueError` for a decision that is not in the pending requests. `claim_turn` returns each decision of the turn, so in 2b the kit runner must keep only the decisions of the pending calls.
