# Version 0.1 plan

Version 0.1 has the core app, `contrib.codex`, `contrib.datastar` and `contrib.celery`. It has chat and approvals, and no tools.

The design is in the Vintage Eye repository: `docs/research/admin-ai-chat/PACKAGE.md` and `BRIEF.md`.

## Method

Each slice ends with green tests, one commit and a short report to the user.

## Slices

| # | Slice | State |
|---|---|---|
| 1 | `kit`: specs, roles, event DTOs, history JSON, errors, `TurnRunner` | Done |
| 2a | Core app: models, migrations, DTOs, errors, repositories, read-only admin, `kit/transcript.py` | Done |
| 2b | Core app: settings, extension points, checks, composition, services, `run_turn`, signals | Done |
| 3 | Redis Stream transport and the `nh3` sanitiser | Done |

## Decisions

1. The send, approve and stream views live in `contrib.datastar`. The core app has services only.
2. One `messages` JSON field for each conversation.
3. Fixed models with a `metadata` field. No swappable models.
4. One column on `Turn` for 7 `RunUsage` counters: `requests`, `tool_calls`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_write_tokens` and `output_reasoning_tokens`. No audio counters and no `cost`.
5. A `redis` service in `compose.yml` and in CI, for the transport tests.
6. Fernet from `cryptography` for the Codex tokens. Confirm in slice 6.
7. The package uses `datastar-py` only, not `django-datastar`. `django-datastar` 0.2.0 excludes Django 6.1.
8. Primary keys are prefixed ULIDs from `python-ulid`: `cnv_`, `trn_` and `apr_`. `ids.py` has one generator for each prefix.
9. `PendingApproval.tool_call_id` is unique for each turn, not across all turns. The approve button sends `PendingApproval.id`.
10. `Conversation` has no `revision` field. The row lock and the active-turn constraint make the turns run one at a time.
11. `Turn.prompt` keeps the user message. Nothing clears it. A failed turn clears `Conversation.pending_approvals` and keeps `messages`.
12. The repositories return their own DTOs from `dtos/`, and raise the errors in `errors.py`.
13. A project uses only the `build_*` functions of `composition.py`, the DTOs, the errors, the settings and the signals. Rule 2 of `PACKAGE.md` section 10 in Vintage Eye needs this text.
14. `SPECS`, `MODEL_FACTORY`, `EVENT_TRANSPORT` and `TASK_RUNNER` have no default. `PERMISSION` defaults to `StaffPermission`, an active staff user. There is no default OpenAI model factory and no detection of `contrib.celery`.
15. `ready()` imports `checks.py`, and does nothing else.
16. If the task runner refuses a turn, the turn fails with `enqueue_failed`, and the error goes to the caller.
17. The page read also checks the permission.
18. A transport error only logs and drops the event. A signal receiver error only logs. Neither stops a turn.
19. A failed turn records its code: `agent_not_found`, or a code from `error_code_for()`. `run_turn` does not raise for it.
20. Each turn has one Redis Stream, with the key `dj_pydantic_agents:turn:<turn_id>`. Each event sets a TTL of 1 hour again, and Redis trims the stream to about 10,000 events. These values are constants, not settings.
21. `EventTransport.read` is an async generator. It yields `None` after 15 seconds with no event, so that the view can send a keep-alive. It stops after a final event: `approval_requested`, `turn_done` or `turn_failed`. A caller that stops early calls `aclose()`.
22. `SANITIZER` defaults to `Nh3Sanitizer`. It runs Markdown with `fenced_code` and `tables`, then `nh3.clean()` with a fixed tag list. There is no `img`, no `class` and no `style`. Links keep `href` and `title`, with the schemes `http`, `https` and `mailto`, and get `rel="noopener noreferrer"`.
23. `REDIS_URL` has no default. The check `E005` finds a missing value when `EVENT_TRANSPORT` is the Redis transport or a subclass of it.
24. `EVENT_TRANSPORT` keeps no default, as decision 14 says.
25. The core dependencies are `redis>=8.0`, `nh3>=0.3.7` and `Markdown>=3.10.2`. The tests use Redis 8 on host port 6380.
26. `contrib.celery` is a Django app. The project adds `dj_pydantic_agents.contrib.celery` to `INSTALLED_APPS`, so that `app.autodiscover_tasks()` finds the task. The check `E006` finds a missing app. It compares strings only, so the core app does not import `celery`.
27. The task `dj_pydantic_agents.run_turn` calls `entry.run_turn()` and does nothing else. It has `ignore_result=True`, no retry and no `acks_late`. A second delivery does nothing, because only a queued turn runs.
28. `CeleryTaskRunner.enqueue` sends the task in `transaction.on_commit()`. The services call it with no open transaction, so a broker error reaches the service, and the turn fails with `enqueue_failed`.
29. `CELERY_QUEUE` selects the queue. The default `None` selects the default Celery queue.
30. The package has no time limit settings. A project sets them for the turn task with `CELERY_TASK_ANNOTATIONS`. `README.md` shows an example.
31. The extra `celery` needs `celery>=5.6.3`, the version of Vintage Eye. CI installs each extra in both jobs.
32. `db.database_sync_to_async()` runs a function in the sync thread of the request, with `thread_sensitive=True`. Before and after the call, it closes each open connection of that thread that is not in a transaction. It does not use `close_old_connections()`, because that function can open a connection. After a cancellation, it waits until the function returns.
33. The text combiner in `kit` publishes at most one text event each 75 milliseconds. Each other event, and the end of a run, publish the waiting text first.
34. `Turn.status_changed_at` holds the time of the latest status change. A queued or running turn with no change for `STALE_TURN_SECONDS` (default 1800) is stale. `open_turn_stream()` fails it with `worker_lost`, with a conditional update. There is no background sweep.
35. The package writes only the views that return patches: send, approve and stream. The project writes each full page and the "New conversation" view.
36. The stream view reads the database one time, through `open_turn_stream()`. Then it reads only the transport, from `START_EVENT_ID`. An `approval_requested` event with only decided tool calls is from an earlier run. The view then reads again after its event ID.
37. A stream lives 60 seconds at most. Then the view sets the signal `_djpaStream` to the time in microseconds, and the `data-effect` of the reply opens a new stream. The timeout is around each read, not around a `yield`.
38. A text event renders the full text with the sanitiser, into the inner HTML of the reply text. The end of a run replaces the reply element with `run_end.html` (mode `replace`). A new approval stop sends the reconnect signal, because the event has no approval IDs. The next snapshot renders the cards.
39. The forms send `contentType: 'form'`, with the CSRF token in the `X-CSRFToken` header. So the signals of the project page do not go to the package views. The approval form has two submit buttons with `name="approved"`.
40. The statuses: 404 for `ConversationNotFound` and `AgentNotFound`, and 403 for `AgentAccessDenied` and for a user who is not logged in. 409 for `TurnInProgress` and `ApprovalNotPending`, and 400 for a bad form.
41. `TurnNotQueued` replaces the error of the task runner, with the original error as its cause. Then the send view and the approve view show an error line and an open form, with status 200.
42. The templates are plain Django templates with `djpa-` class names. The package has no JavaScript, no CSS and no Cotton. A project overrides a template at the same path. The extra `datastar` needs `datastar-py>=1.0.2`.
43. `tests/demo/` is a small project for a test in a browser. It uses the Redis transport, a scripted model and a thread task runner.

## Facts from the research

The reports are in `.pi/research/v0.1/`.

- A turn calls `run_sync(message_history=..., deferred_tool_results=..., event_stream_handler=...)`.
- Do not pass `conversation=`. With it, the default `request_limit` of 50 counts the requests of the whole conversation. The package keeps the conversation total in its own columns.
- The event handler must be `async`. The first text piece is in `PartStartEvent`. The next pieces are in `PartDeltaEvent`.
- An approval resume does not trigger the Codex "suspended run" error. That error needs OpenAI background mode. Keep background mode off.
- `OpenAICodexOAuthFlow.exchange_code()` does not check `state`. The login service must check it.
- The refresh lock of the Codex provider works in one process only. Slice 6 needs a lock across processes.
- A new prompt fails when the history ends with a tool call that has no result. This happens after a failed resume. `pydantic_ai.messages.repair_messages()` closes the open calls. The kit runner calls it before each new prompt.
- `DeferredToolRequests.build_results()` raises `ValueError` for a decision that is not in the pending requests. `claim_turn` returns each decision of the turn, so the kit runner keeps only the decisions of the pending calls.
- `inspect.signature()` and `create_autospec()` evaluate the annotations by default. The system checks use `annotation_format=Format.FORWARDREF`, so a project can import its annotation types for type checks only.
- The types of `redis` cover each `XREAD` reply shape. The default client returns the RESP2 shape `[[key, [(event_id, fields), ...]]]`. The tests against Redis 8 confirm this with `redis` 8.0.0 and 8.1.0.
- A bad stream entry must also move the last event ID. If it does not, `XREAD` returns the same entry again and again.
- Vintage Eye runs `celery` 5.6.3 on Python 3.14 in production. The 5.6.3 metadata has no 3.14 classifier.
- Datastar 1.0.2 (`datastar-pro.js` of Vintage Eye, and the free bundle):
  - The default `retry: "auto"` opens a stream again after a network error only. A normal close gives no retry.
  - For `@get`, `openWhenHidden` defaults to false. A hidden tab closes the stream and opens it again when the tab is visible.
  - `requestCancellation: "cleanup"` stops the request when its attribute or its element goes.
  - The mode `replace` calls `replaceWith()`, so a fragment can have more than one root element.
  - With `contentType: "form"`, Datastar also sends the name and the value of the submit button.
  - Datastar reads the patches of a status 200 reply only.
- A browser test confirmed the reconnect after 60 seconds and the reconnect after a hidden tab.
- A JavaScript number is exact up to about 9.0e15. `time.time_ns()` is about 1.8e18, so the signal holds microseconds.
- Under ASGI, Django warns about a sync iterator in a streaming response. Each package response uses an async iterator.
- A cancel at a `yield` inside `asyncio.timeout()` reaches the code of the consumer, so the timeout cannot convert it.
- Celery 5.6.3 has `DjangoTask.apply_async_on_commit()`. The Django fixup makes `DjangoTask` the default task class only when the project app sets no task class. So the runner calls `transaction.on_commit()` itself.
